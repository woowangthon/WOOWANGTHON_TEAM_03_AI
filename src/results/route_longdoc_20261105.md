입력: RS-6 Y-01 "개인 고객 대출 심사 및 거래 현황 검토서"(가상 데이터, 11쪽 16,610자) + 지시문 "이 대출 심사보고서를 영문으로 번역하고, 심사 의견·상환능력·위험 요인·승인 조건을 정리한 한글 요약본을 작성해 주세요." = 16,679자.
정답표가 전제한 경로는 외부(가린 뒤 전송).

## 1. 전문을 보내면 실패한다

tev1(tev1-cpu) 컨텍스트 8,192토큰. 전문 16,679자 = 8,355토큰 → `/v1/systemone HTTP 400: request (8355 tokens) exceeds the available context size (8192 tokens)`.
서버(`/analyze`)는 이 예외를 잡아 `route: null`, `mode: degraded`, 결정은 사내 폴백으로 처리하므로, 약 1만 2천 자를 넘는 문서는 항상 경로 판정 없이 사내로 갔다. 수락 검사(accept_run)는 예외로 중단됐다.

## 4. 결정

- `route.py`에 `ROUTE_MAX_CHARS = 6000`을 두고 앞부분만 보낸다(줄 끝에서 끊고 생략 표시). 응답에 `state_chars`, `truncated` 추가.
- 기본 기준 문구는 v1 유지. 긴 한국어 보고서의 번역·요약 요청이 사내로 가는 문제는 남아 있다.
- 남은 과제(별도 판단): 사내 처리(`/answer_local`)는 한 번에 약 6,000자까지만 다룰 수 있으므로, 그보다 긴 문서를 사내로 보내는 판정은 애초에 성립하지 않는다. "길이가 사내 처리 한계를 넘고 차단·내부 전용 사유가 없으면 외부(가림·승인)"라는 결정 규칙 추가를 PM과 논의할 것.
