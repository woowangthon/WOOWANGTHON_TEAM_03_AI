# 모델링 인터페이스 v1 (2026-10-29)

대상: 백엔드. 모델링이 넘기는 것은 전부 `src/` 안의 순수 Python 함수이고 DB를 만지지 않는다. Ollama는 집 PC `127.0.0.1:11434`(localhost 금지, IPv6 대기로 호출마다 2초). 수치는 모두 집 PC 실측이다.

## 요청 하나의 호출 순서

| 단계 | 호출 | 반환 | 지연 |
|---|---|---|---|
| 1a 즉시 탐지 | `detect(text, use_llm=False)` | spans(규칙+사전+NER), timing | 규칙 0.1~0.5ms + NER 10~60ms |
| 1b 정밀 탐지 | `detect(text)` | spans(즉시 경로 + 30B 병합), rule_spans, llm_spans, timing, warnings, dropped | 구간 없음 0.8초, 5~10개 2~3초, 13~18개 6~7초, 3,600자 넘는 글은 조각당 3~10초 |
| 2 라우팅 | `route(text)` | {choice: local/external/block, probabilities, confidence, seconds} | 0.7~1.3초. 1b와 동시에 불러도 됨(동시 호출 시 전체 1.42→1.04초) |
| 3 결정 | `decide(text, spans, route)` | {action, needs_approval, reasons, warnings} | 0ms |
| 4 가림 | `mask(text, spans, policy)` | {masked, mapping, entries, unmasked, policy} | 0ms |
| 5 외부 요청 | `instruction_for_external() + "\n\n" + masked` | 외부 LLM 호출은 백엔드 | - |
| 6 복원 | `restore(answer, mapping)` | 원문이 복원된 답변 | 0ms |

2단계 카드: 1a 결과로 하이라이트를 먼저 그리고(접수 응답에 포함 가능), 1b가 끝나면 카드를 갱신한다. 긴 문서는 1b가 수십 초 걸리므로 "정밀 검사 진행 중"과 예상 시간을 표시한다. `route`가 실패하면 `decide(text, spans, None)`을 부르면 사내 처리로 폴백한다.

## span 형식

`{start, end, text, label, sources}`. label은 company, project, doc_no, price, person, contact, biz_no, other. sources는 `rule:<규칙명>`, `dict:<파일>`, `ner:<모델>`, `llm`, `propagate` 중 여럿. 위치는 원문 기준 문자 오프셋이라 그대로 하이라이트에 쓴다.

## 정책(등급)

`policy = {"mask_person": False, "mask_company": True}`가 기본. 등급 1(식별번호·금액·연락처·사업자번호·사업명·회사명)은 항상 가림, 등급 2(사람)는 `mask_person`일 때만, 회사명은 `mask_company`로 내릴 수 있다. 가리지 않은 구간은 `unmasked`에 사유와 함께 돌아오므로 카드에서 노란 토글로 보여주면 된다. 자리표는 `[[ORG_1]]`, `[[AMT_2]]`, `[[ID_3]]`, `[[PERSON_4]]`, `[[CONTACT_5]]`, `[[BIZNO_6]]`, `[[PROJECT_7]]`이고 같은 표기는 같은 번호다.

## 결정 규칙(decide)

통째 유출 차단(구간 4개 이상·라벨 3종 이상 + "전부 정리·표로 취합" 요청), 사업자·주민번호 3개 이상 차단, "대외비·외부 공유 금지·내부 공유용" 표기는 사내 강제, "가리지 마·마스킹 없이" 류는 가림 유지 + warnings(보안팀 로그), tev1의 block은 확률 0.6 이상만 인정, local·external 차이 0.1 미만이면 구간 있을 때 외부+승인 카드. `needs_approval`은 external이고 구간이 있을 때 True.

## 오류와 경고

30B가 실패하거나 90초를 넘기면 예외 없이 즉시 경로 결과만 돌아오고 `warnings`에 사유가 붙는다. 생성이 상한(768토큰)에서 끊기면 완성된 구간만 쓰고 경고를 붙인다. 지시 삽입 문장은 30B 입력에서 지우고 구분자로 감싸 보내므로 백엔드가 따로 할 일은 없다. warnings는 카드에 띠로, 로그에는 그대로 남긴다.

## 환경

Python 3.12, `.venv`에 torch(CPU)·transformers(NER용, 첫 호출 모델 로딩 8~14초 → 서비스 시작 시 `detect("예열", use_llm=False)` 한 번 권장). Ollama 환경변수 `OLLAMA_MAX_LOADED_MODELS=3`, `OLLAMA_KEEP_ALIVE=-1`(없으면 30B·tev1·bge-m3 순환 시 30B 재로드 14~17초). 사전 `src/data/dict/companies.txt`, `projects.txt`는 한 줄에 하나, `|`로 별칭. 제품에서는 보안 담당자가 거래처·사업코드를 등록하는 자리이고, 직원이 카드에서 확정한 이름을 여기에 넣는 것이 되먹임이다.

## 함께 정할 것

1. 모델 코드를 집 PC에서 한 번 호출로 쓰는 서비스(`/analyze`: 1a·1b·2·3·4 묶음)로 포장할지, 백엔드가 함수를 직접 부를지. 터널 지연을 생각하면 서비스 쪽이 유리하다.

3. 응답 형식에 1a·1b 두 단계를 어떻게 담을지(상태 조회 API가 두 번 갱신).
