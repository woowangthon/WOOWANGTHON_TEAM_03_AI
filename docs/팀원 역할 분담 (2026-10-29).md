## 백엔드

### 맡는 것 (흐름도 번호)

- **접수 API** (A-1): 요청 번호 발급, 원문·시각을 requests 테이블에 대기 상태로 저장, 규칙 탐지를 즉시 호출해 응답에 실어 반환. 뒷단 처리(30B, tev1)는 백그라운드 작업으로 넘김.
- **상태 조회 API** (A-폴링): 요청 번호로 현재 상태·구간·카드·답변을 돌려줌. 화면이 2초마다 호출.
- **탐지·라우팅 호출** (A-2, A-3): 모델링이 넘기는 `detect(text)`와 `route(text)` 함수를 백그라운드 작업에서 호출. 집 PC Ollama는 Cloudflare 터널 주소 + API 키로 호출.
- **결정 분기** (A-4): 라우팅 결과와 구간 유무로 승인 카드 / 로컬 답변 / 차단 / 카드 없이 외부 전송 네 가지로 보냄.
- **승인 API** (A-4.2): 직원이 고른 최종 구간 목록을 받아 approvals에 기록하고 가림 단계로 넘김.
- **가림·복원** (A-5): 구간을 뒤에서 앞으로 `[라벨_n]` 자리표시자로 치환(같은 값은 같은 번호), 토큰 맵은 요청 번호에 묶어 DB에만 저장. 외부 LLM 호출 후 자리표시자를 되돌리고 남거나 깨진 표시자 수를 복원률로 기록.
- **외부 LLM 호출**: Anthropic API(팀 결정 대기). 프롬프트에 "대괄호 자리표시자는 바꾸지 말라" 지시 포함. API 키는 서버 환경변수.
- **로그 DB** (B-6): requests, spans, approvals, dict, allowlist, 요청 벡터(vector(1024)) 테이블. 원문은 requests에만.
- **집계 API** (B-7): 날짜·경로별 COUNT, 라벨별 분포, 공격 세트 탐지율. 원문은 절대 내보내지 않음.
- **학습 배치** (B-8): 승인 구간 → dict, 해제 구간 → allowlist. 밤마다 + "즉시 반영" 스위치.
- **벡터 조회** (B-9): 요청마다 bge-m3로 임베딩 → pgvector 유사도 검색 top-k → 모델링이 정한 형식으로 유사 사례 반환. 새 벡터 저장.
- **헬스체크·폴백** (C): 5분마다 터널 너머 Ollama 응답 확인, 실패 시 "간단 모드"(규칙 탐지 + 4B 답변) 플래그.
- **배포**: Oracle VM에 Docker(PostgreSQL + 서버), systemd 재시작, 심사 종료(11-21)까지 URL 유지.

### 모델링과의 접점

- 모델링이 주는 것: `detect(text) -> spans[{start,end,text,label,sources}]`, `route(text) -> {choice, probabilities}`, 유사 사례를 30B 프롬프트에 넣는 함수. 전부 순수 Python 함수이고 DB를 만지지 않는다.
- 백엔드가 주는 것: `similar_cases(text, k)`가 돌려줄 사례의 형식(과거 요청 본문, 그때의 승인·해제 구간) 합의. requests 테이블에 단계별 지연(ms) 칼럼.
- 중요: Ollama 호출은 반드시 `127.0.0.1` 또는 터널 주소. `localhost`는 이 PC에서 호출마다 2초 붙는다. `num_ctx`는 4096 고정(바뀌면 30B 14초 재로드).

### 주차별

- W1: DB 스키마, 접수·상태·승인 API, 가림·복원, 모델링 함수 연결, 로컬에서 끝까지 한 번 도는 것.
- W2: 집계 API, 학습 배치, 벡터 조회, 폴백, Oracle VM 배포 + Cloudflare 터널 + API 키 검사.
- W3: 재생 스크립트와 함께 부하 확인, 로그 정리, 안정화. 11-14 코드 동결.

## 자료수집

### 맡는 것

- **50개 샘플 정답 확정** (모델링 W1 산출물 검토): 지금 10개(S01~S10) + 밤 배치가 만든 후보 40건을 읽고, 민감 구간 정답을 고치고, 사전에 없는 회사명 15건 이상이 들어가도록 조정. "이 구간은 왜 민감한가"를 note에 한 줄.
- **공격 세트 30건** (B-7-2): 밤 배치가 만든 후보 30건을 검토해 기법별(번호 변형, 금액 한글, 영문 회사명, 문맥 분산, 지시 삽입, 통째 유출) 고르게 확정. 각 건에 정답 구간과 기대 결과(mask/block).
- **사전**: 실제 방산 원청 5~6곳, 가상 협력사 5곳, 사업명 3~5개. 변형 표기(영문, 약칭)도 함께.
- **인터뷰 1건 이상**: 방산 협력 중소기업 품질 담당 또는 보안 담당. 질문 5개(외부 AI 금지 여부, 실제로 뭘 붙여 넣고 싶은가, 가장 두려운 유출, 승인 절차를 견딜 수 있는가, 보안팀이 보고 싶은 숫자). 녹취 대신 메모. 문제정의 20점의 근거.
- **문제정의 자료**: 외부 AI 금지 기업 비율, 유출 사례 2~3건, 방산 협력사 보안 규정 근거(출처 명시).
- **발표 PDF 초안** W2 말까지 1차, 모델링·백엔드 수치를 받아 W3에 완성. 영상 대본.

### 모델링과의 접점

- 정답 형식은 samples.jsonl 그대로(JSON 한 줄에 id, category, route, text, spans, note). 수정은 JSON 편집으로. 모델링이 평가를 다시 돌려 숫자를 준다.
- 샘플 검토 기준: 공개 규격 번호(MIL-, ASTM, AWS, ISO, KS), 치수·수량·날짜는 민감 구간이 아니다. 회사명·사업명·식별번호·금액·사람·연락처·사업자번호는 민감 구간이다.

### 주차별

- W1: 샘플 50개 확정, 사전, 인터뷰 섭외.
- W2: 공격 세트 확정, 인터뷰 완료, 문제정의 자료, 발표 초안.
- W3: 발표 PDF 완성, 영상 대본, Notion 페이지 글.

- **보안팀 대시보드** (B-7): 집계 5종 그래프, 라벨별 분포, 공격 탐지율 패널(실시간), "즉시 반영" 스위치. 30초 갱신.

- 모델링에서 받을 숫자: 탐지 재현율·오탐, 라우팅 일치율, 지연 p50/p95, 되먹임 전후 비교표. 발표 "구현 25점·AI 활용 10점"의 근거.
