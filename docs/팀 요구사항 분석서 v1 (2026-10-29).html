2. 백엔드 요청 (흐름도 번호별)

스택 제안: FastAPI + Uvicorn, SQLAlchemy 2 + psycopg 3(또는 asyncpg), 마이그레이션은 Alembic 대신 schema.sql 한 장으로 시작, 외부 호출은 httpx, 외부 LLM은 anthropic SDK, 배치는 APScheduler(Redis 불필요), 배포는 docker compose(gateway + db) 뒤에 Caddy(HTTPS 자동). 모델링 함수는 집 PC의 "모델 서비스"로 포장해 HTTP로 부른다(아래 5절). 즉시 경로만은 서버에도 같은 코드를 설치해 터널 없이 돌린다.

백엔드①접수 API와 상태 조회 (2초 폴링)
구축
POST /requests: 본문·요청자·정책을 받아 행을 만들고, 즉시 탐지를 동기로 돌려 1차 하이라이트를 응답에 넣고, 정밀 분석을 백그라운드 작업으로 넘긴다. GET /requests/{id}: 상태 기계와 두 단계 결과를 돌려준다. 상태는 received → instant_done → analyzing → awaiting_approval | local_processing | sending | blocked → answered | failed.
입출력
POST /requests
{ "text": "아래 부적합 보고서를 영문으로…", "requester": "qa.kim", "policy": {"mask_person": false} }
→ 202 { "id": "r_01J…", "status": "instant_done",
        "instant": { "spans": [ {"start": 72, "end": 85, "text": "NCR-2026-0147", "label": "doc_no", "sources": ["rule:doc_code"], "tier": 1} ],
                     "ms": 48 } }

GET /requests/r_01J…
→ 200 { "status": "awaiting_approval",
        "instant": {…}, "full": { "spans": [...], "warnings": ["지시 삽입 감지: …"], "timing": {"llm_total_s": 5.8, "chunks": 1} },
        "route": {"choice": "external", "probabilities": {"local": 0.3, "external": 0.55, "block": 0.15}},
        "decision": {"action": "external", "needs_approval": true, "reasons": ["tev1 external 0.55"]},
        "mask_preview": "… 문서번호: [[ID_1]] | 고객사: (주)[[ORG_1]] …",
        "progress": {"stage": "full", "chunk": 1, "chunks": 1, "eta_s": 0} }
도구
FastAPI BackgroundTasks로 시작하고, 동시 요청이 늘면 asyncio.Queue 워커 하나로 바꾼다(집 PC GPU가 하나라 30B 호출은 어차피 순차). ID는 ULID.
완료 조건
접수 응답 300ms 이내(즉시 탐지 포함). 폴링 2초 간격에 상태 전이가 보인다. 시연 문서 6건을 넣으면 D1·D4는 승인 없이, D2는 사내, D3·D6은 승인 카드, D5는 차단 상태가 된다.
요청문
FastAPI로 게이트웨이의 접수·상태 조회 API를 만들어 주세요. POST /requests는 {text, requester, policy}를 받아 PostgreSQL requests 테이블에 저장(ULID id)하고, 모델링 패키지의 detect(text, use_llm=False)를 동기로 호출해 즉시 구간(start, end, text, label, sources, tier)을 응답에 넣은 뒤, 백그라운드 작업으로 모델 서비스 POST /analyze를 호출해 결과를 저장합니다. GET /requests/{id}는 status(received, instant_done, analyzing, awaiting_approval, local_processing, sending, blocked, answered, failed)와 instant·full 두 단계 구간, route, decision, mask_preview, progress(단계, 조각 n/m, 예상 초)를 JSON으로 돌려줍니다. CORS는 Vercel 도메인만 허용하고, 프론트 호출은 Authorization: Bearer <팀 토큰>으로 막아 주세요.
백엔드② 2-1 · 3.1모델 서비스 호출과 폴백(간단 모드)
구축
집 PC 모델 서비스를 부르는 클라이언트 하나. POST /detect/instant(규칙·사전·이름 모델, 50ms)는 서버 안의 같은 패키지로 대체 가능. POST /analyze(탐지 + 라우팅 + 결정 + 가림 미리보기, 2~8초, 긴 글 수십 초)는 터널 너머. 시간 제한 120초, 실패 1회 재시도, 그래도 실패하면 간단 모드: 즉시 경로 결과만으로 결정(규칙에 구간 있으면 승인 카드, 차단 규칙은 그대로 적용)하고 카드에 "정밀 검사 실패" 경고.
입출력
POST https://모델주소/analyze   헤더 X-API-Key
{ "text": "...", "policy": {"mask_person": false}, "examples": [ {"text": "...", "spans": [...]} ] }   ← examples는 ⑨가 채움(text는 과거 사례 발췌, 없으면 생략)
→ { "spans": [...], "rule_spans": [...], "llm_spans": [...], "warnings": [...], "timing": {...},
    "route": {...}, "decision": {...}, "mask": {"masked": "...", "mapping": {"[[ORG_1]]": "(주)한빛에어로"}, "entries": [...], "unmasked": [...]} }
도구
httpx AsyncClient(연결 5초, 읽기 120초), tenacity 재시도 1회, 결과는 그대로 JSONB 컬럼에 저장.
완료 조건
집 PC를 끄고 요청하면 10초 안에 간단 모드로 카드가 뜬다. 켜면 정밀 결과로 갱신된다.
요청문
게이트웨이에서 집 PC 모델 서비스를 부르는 클라이언트를 만들어 주세요. httpx.AsyncClient로 POST {MODEL_BASE}/analyze에 {text, policy, examples}를 보내고 X-API-Key 헤더를 붙입니다. 연결 5초·읽기 120초 제한, 실패 시 1회 재시도, 그래도 실패하면 간단 모드로 전환합니다. 간단 모드는 서버에 설치된 모델링 패키지의 detect(text, use_llm=False)와 decide(text, spans, None)만으로 결정하고 warnings에 "정밀 검사 실패: 규칙 결과만 적용"을 넣어 상태를 awaiting_approval 또는 blocked로 보냅니다. 응답은 requests 행의 analysis(JSONB)에 통째로 저장하고, 상태를 analyzing → 결정에 맞게 바꿔 주세요. 모델 서비스 응답 시간(ms)도 열에 기록해 집계에 쓸 수 있게 해 주세요.
백엔드④ 4.1 · 4.2 · 4.3결정 저장, 승인 큐, 승인 API, 사내 답변, 차단
