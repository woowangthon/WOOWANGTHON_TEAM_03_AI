# AI 교환기 동료 · 모델 v1 동작 설명 (2026-10-29)

모델링 담당이 알아둘 것을 한 장에 모았다. 발표 Q&A와 팀원 설명에 그대로 쓴다. 수치는 전부 집 PC(RTX 5060 Ti 8GB) 실측이고, 정답은 생성기가 붙인 미검토 라벨이다.

## 1. 한 줄 요약

직원이 보낸 글 하나를 네 층이 차례로 본다. 규칙·사전·NER이 1ms~60ms에 "아는 것"을 잡고, 30B 로컬 모델이 2~7초에 "모르는 이름"을 채우고, tev1이 경로(사내·외부·차단)를 제안하고, 결정 규칙이 최종 처리를 정한다. 외부로 갈 글은 자리표로 가린 뒤 보내고, 돌아온 답에서 자리표를 원문으로 되돌린다.

## 2. 흐름 (요청 하나)

| 순서 | 무엇 | 걸리는 시간 |
|---|---|---|
| ① 즉시 탐지 | 규칙 + 사전 + NER(사람 이름) | 규칙 0.1~0.5ms, NER 10~60ms |
| ② 정밀 탐지 | 30B가 지시 문장을 지우고 구분자로 감싼 본문을 받아 놓친 구간을 찾음. 3,600자 넘으면 조각으로 | 구간 없음 0.8초, 5~10개 2~3초, 13~18개 6~7초 |
| ③ 라우팅 | tev1(0.8B)이 "이 작업에 외부 모델이 필요한가"를 영문 기준으로 판정 | 0.7~1.3초, ②와 동시 호출 가능 |
| ④ 결정 | 차단·사내 강제·애매·경고 규칙 적용 | 0 |
| ⑤ 가림 | 등급 정책에 따라 자리표로 치환 | 0 |
| ⑥ 외부 호출 → 복원 | 안내문 + 가림 본문을 외부 LLM에, 답의 자리표를 원문으로 | 외부 모델 시간 |

카드는 두 번 그린다. ①이 끝나면 하이라이트를 바로 보이고, ②가 끝나면 갱신한다. 긴 문서(수십 초)에서는 이게 필수다.

## 3. 층별 역할과 한계

**규칙·사전 층.** 형식이 있는 것과 등록된 것만 잡는다. 결정적이고 오탐이 0이며 지시 삽입에 영향받지 않고 전각·띄어쓰기 변형에 강하다. 앵커(단서어·직함·사전)가 없는 이름, 미등록 회사, 줄바꿈으로 쪼갠 번호, 초성은 못 본다.

**NER 층.** 공개 한국어 개인정보 NER 모델(`atonlee/koelectra-ko-pii-ner`, CPU)로 사람 이름만 잡는다. 성씨로 시작하는 2~3음절(복성 3~4)만 인정하고 점수 0.85 이상, 영문 이름은 두 단어 이상·0.9 이상·Co./Inc. 제외. 회사명은 "한빛에"처럼 부분으로 끊어 쓰지 않는다.

**30B 층.** `qwen3:30b-a3b-instruct-2507`(토큰당 약 3B 활성). 사전에 없는 회사명·사업명, 단서 없는 이름을 찾는다. 약점은 다섯 가지다. 무해해 보이는 글에서 이름을 건너뜀, 본문 속 지시에 복종(→ 지시 문장 공백 처리 + 구분자 감싸기로 막음), 수량·날짜·규격을 금액·사업명으로 라벨(→ 상식 필터), 같은 입력에 드물게 다른 출력, 값이 반복되는 글에서 생성 폭주(→ 768토큰 상한·90초 제한).

**tev1 층.** 경로 제안만 한다. 영문 기준(v1)이 번역·요약 같은 외부 필요 작업을 잘 가르지만 단순 편집 작업의 40%를 외부로 보낸다. 구간이 없으면 외부로 가도 유출이 아니므로 보안엔 무해하고, 카드의 "사내로 처리" 토글로 보완한다. 통째 유출 차단은 tev1이 못 하므로 규칙이 한다.

**혼합.** 세 탐지 결과의 합집합. 겹치면 규칙 라벨이 이긴다. 회사·사람 구간은 법인 접두어를 벗긴 표기가 본문에 다시 나오면 그 자리도 가린다(전파). 사전에 없는 말이 10회 넘게 나오면 상용구로 보고 전파하지 않는다.

## 5. 30B 처리 세부 (src/detect_llm.py, detect.py)

- 시스템 프롬프트: 라벨 7종 설명 + 규칙 4개(원문 그대로 복사, 공개 규격·재질 기호 제외, 치수·수량·날짜 제외, 없으면 빈 배열) + C 모드 꼬리("규칙이 찾은 구간: …, 이것들은 빼고 놓친 것만, 특히 이름·회사·사업명") + 구분자 규칙.
- 입력: 지시 삽입 문장을 같은 길이 공백으로 지우고 `<<<문서 시작>>> … <<<문서 끝>>>`으로 감싼다. 3,600자 넘으면 줄 경계에서 조각 내 순차 호출.
- 출력: JSON 스키마로 라벨을 enum 강제, 원문에 없는 글자는 버림(환각 방지), 생성 상한 768토큰, 90초 제한, 끊긴 JSON은 완성된 객체만 건짐, 호출 실패 시 즉시 경로 결과만 쓰고 경고.
- 상식 필터: 수량·기간·날짜를 금액으로 낸 것, "A사" 익명 호칭, 공개 규격·측정값, 소문자 영문 구절, "[대외비]" 같은 머리말 표식 삭제.
- 비결정성: 같은 입력 3회에 흔들림 0이었지만 어제 1건 관찰. 1건 차이는 재실행으로 확인.

## 6. 결정 규칙 (src/decide.py)

| 규칙 | 조건 | 결과 |
|---|---|---|
| 개인정보 묶음 | 사업자·주민번호 구간 3개 이상 | 차단 |
| 통째 유출 | 구간 4개 이상·라벨 3종 이상 + "전부·모든·한눈에 … 정리·취합·표로·엑셀" 요청 | 차단 |
| 내부 전용 | 대외비, 외부 공유 금지, 내부 공유용, 사내 공유, 내부 회의 | 사내 강제 |
| tev1 차단 | 차단 확률 0.6 이상일 때만 인정 | 차단 |
| 애매 | 사내·외부 확률 차이 0.1 미만 | 구간 있으면 외부+승인 카드, 없으면 사내 |
| 지시 삽입 | 가리지 마, 마스킹 없이, no masking, bypass masking 등 | 차단하지 않고 가림 유지 + 경고(보안팀 로그) |

승인 카드는 외부이고 구간이 있을 때 뜬다. 라우팅 실패 시 사내 처리로 폴백.

## 7. 등급 정책과 가림·복원 (src/mask.py)

| 등급 | 라벨 | 처리 |
|---|---|---|
| 1 | 식별번호, 금액, 연락처, 사업자·주민번호, 사업명, 회사명 | 항상 가림(회사명은 정책으로 내릴 수 있음) |
| 2 | 사람 이름 | 탐지는 하되 가림은 토글, 시연 기본 끔 |
| 3 | 직급·부서, 날짜, 수량, 치수·물성, 공개 규격, 재질 기호 | 가리지 않음 |

자리표는 `[[ORG_1]]`, `[[AMT_2]]`, `[[ID_3]]`, `[[PERSON_4]]`, `[[CONTACT_5]]`, `[[BIZNO_6]]`, `[[PROJECT_7]]`. 번역에서 살아남도록 언어 중립이고, 같은 표기는 같은 번호다. 외부 요청 앞에 "자리표를 그대로 유지하라" 안내문을 붙이고, 답에서 `[[ ORG_1 ]]`, `[ORG_1]`, `[[org-1]]` 같은 변형도 되돌린다. 모르는 자리표는 추측하지 않고 둔다. 수치를 가리지 않고 식별번호·사업명을 가려 "어느 부품의 수치인지"를 끊는 것이 설계 원칙이다.

## 9. 알려진 약점과 주의

- 긴 문서는 시간이 민감 구간 수에 비례한다(구간당 약 0.35초 생성). 2단계 카드 없이는 못 쓴다. 규칙 구간을 자리표로 가린 본문을 30B에 보내는 M 모드는 밤 배치 4(128건 + 긴 문서 2건)에서 기각됐다. 자리표를 본 모델이 나머지를 찾지 않아 후보 세트 재현율 100→90%, 자리표 옆 일반 명사를 회사·사업명으로 내 오탐 17→38, 긴 문서 출력도 줄지 않았다(2,513→2,848토큰). 30B에 "다시 나열하지 마라"는 지시는 짧은 글에서만 먹히고 긴 글에서는 안 먹힌다. 현실적 대책은 2단계 카드와 긴 문서 사전 안내다.
- 30B가 128건 중 1건꼴로 반복 생성에 빠진다. 상한으로 20초에 끊기고 결과는 복구된다.
- 영어 이름은 NER 68%, 30B 91%. 영어 문서는 30B 의존도가 높다.
- 지시 삽입 정규식은 설득형 문구를 3/20만 잡는다. 경고는 놓쳐도 가림은 구분자 감싸기가 지킨다.
- 줄바꿈으로 쪼갠 번호(DWG⏎-2025⏎-0417)와 초성(ㅎㅎㅇㅇㄹ)은 못 잡는다.
- tev1은 단순 편집 작업을 40% 외부로 보낸다. 무해하지만 "사내 처리" 시연에는 토글이 필요하다.
- 모든 수치가 30B가 만든 글과 미검토 정답 위에 있다. 자료수집 검토 뒤 재측정해야 발표용이다.

## 10. 운영 주의

Ollama는 반드시 `127.0.0.1`(localhost는 호출마다 2초). 환경변수 `OLLAMA_MAX_LOADED_MODELS=3`, `OLLAMA_KEEP_ALIVE=-1`이 없으면 세 모델 순환 때 30B 재로드 14~17초. `num_ctx` 4096 고정(바꾸면 재로드). NER 첫 호출 모델 로딩 8~14초라 서비스 시작 시 예열. PC 절전은 유휴 3시간이라 밤새 배치는 설정 변경 필요. 프롬프트를 바꾸면 세트 전부 재평가(한 번 넣었다가 오탐이 늘어 되돌린 전례).

## 11. 남은 일

**모델링.** 밤 배치 4 결과로 M 모드 채택 여부, 모델 코드 서비스 포장 여부(백엔드와), RAG 연결(pgvector 뒤, 게이트 0.7), 정답 검토 반영 재측정, 영어 이름 보강, 반복 생성 상한 512 검토, 공격 유형 추가(줄바꿈 번호 정규화), 발표 수치표.

**백엔드에 요청.** 서비스 포장 방식 결정, 상태 조회 API에 두 단계(즉시·정밀) 결과 반영, 승인 카드 데이터(구간·출처·미가림 목록·경고·사유) 전달 형식, 외부 요청에 안내문 선행·응답 복원 호출, 보안팀 로그 필드(지시 삽입 경고·차단 사유), pgvector와 유사 사례 조회 함수, 집 PC Ollama 환경변수·NER 예열, 정책(등급 토글) 저장 위치.

**PM·프론트에 요청.** 카드 UI: 1등급 빨간 고정 하이라이트, 2등급 노란 토글, "사내로 처리" 버튼, "정밀 검사 진행 중 n/m" 표시, 경고 띠, 차단 카드의 사유와 "보안팀 승인 요청". 대시보드 숫자(가림 건수, 차단 건수, 지시 삽입 경고 수, 사례 적중률). 시연 대본은 시연 문서 6건 순서. 팀 결정 여섯 가지 마감. 외부 LLM API 키.

**자료수집에 요청.** 검토표 1차(40)·2차(40)·영어(12) 정답 검토, 특히 생성기가 빼먹은 이름·부품번호 추가. 인터뷰에서 실제 문서 양식(부적합 보고서, 발주서, 견적서, 감사 자료) 확보. 등급 정책(이름 노출 가능 여부, 고객사명 등급)을 방산 협력사 보안 담당자 관점에서 확인. 발표용 문제정의 자료.
